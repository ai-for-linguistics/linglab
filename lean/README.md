# Lean workspace (library `Linglab`, Lean 4.34.1, no dependencies)

The interface only; your theories go in `Linglab/Theories/`. `cd lean && lake build` checks what `Linglab.lean` imports; `linglab lean` also builds every file with fact theorems.
- **Interface:** shared syntax `Linglab/Syntax.lean`; the `Theory` structure and the claim shapes `Holds`/`Fails`: `Linglab/Theory.lean`. The language-neutral specification (for any proof system) is `docs/INTERFACE.md`.
- **Worked example:** `example/lean/Linglab/Toy/` (principles as tagged chunks, four theories, facts, Raw Facts). Copy its pattern.
- **Scope:** `Theory.scope` (default `"complete"`) says what `models` covers. If the list bounds the domain, say so (`scope := "domain size ≤ 3"`): `linglab lean` then records results as "exhaustive within domain size ≤ 3", computations within that bound rather than general proofs.
- **Naming:** in namespace `T_X` (the theory id with `-` replaced by `_`), which defines `theory : Theory`, `theorem F12 : Holds theory <claim>` proves a claim, `theorem F12_fail : Fails theory <claim>` proves its negation; `linglab lean` combines them with the fact's `expected`. The claim must be the fact's spec in `data/statements.json`: `linglab lean` checks each theorem against it and credits only those that match (it says why the others were not credited). Principle code goes between `-- BEGIN principle:P-X` and `-- END principle:P-X` (sizes are measured on these chunks). A theory that cannot say a sentence returns `none` from `translate`: write no theorem, the fact is out of scope. Never leave `sorry`.
